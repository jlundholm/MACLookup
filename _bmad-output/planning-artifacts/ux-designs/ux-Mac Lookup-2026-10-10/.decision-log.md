- **Decision:** Visual direction = `direction-status` — the lookup outcome is promoted to a bold, lamp-lit banner; the accent color encodes the result (green found / amber no-match / red invalid); heavier type, higher contrast; each format row carries a matching status rail.
- **Source artifact:** `.working/direction-status.html` (light + dark palettes, banner lamp, colored rails). Reference for DESIGN.md tokens/Components and EXPERIENCE.md state patterns.
- **Conflict with PRD §10 surfaced:** PRD says accent "approximates Chrome blue" and the popup should be "native, unobtrusive." The Status direction makes **semantic status color** (green/amber/red) the accent and is deliberately the loudest of the four. *Reconciliation to confirm:* keep semantic status color as the outcome signal while keeping the rest native/system-styled; blue reduced to at most the neutral focus ring — or drop it entirely. [OPEN until confirmed]
- **Accessibility note:** outcome is *not* color-only — the banner carries a text state label ("Found"/"Not found"/"Invalid") plus a value string; the colored row rails are redundant decoration. Must preserve the text label for WCAG 1.4.1.

## 2026-10-10 — Discovery closed (decisions)

- **Accent conflict resolved — no blue at all.** The popup is monochrome system colors; **semantic status color is the only color** (green found / amber no-match / red invalid), carried by the banner and row rails. PRD §10's "Chrome blue" note is superseded. Focus ring uses the text/neutral color, not blue.
- **Stakes / audience:** Personal utility, builder-as-user (possibly published later). Accessibility bar: WCAG AA text contrast + full keyboard reachability; not a public-consumer review bar.
- **Popup open behavior:** Field autofocuses on open; empty resting state = neutral placeholder, no error (`FR-2`).
- **Motion:** Subtle ~120 ms cross-fade on result-state change; fully suppressed under `prefers-reduced-motion: reduce`.
- **Voice & tone:** Terse, functional, no personality (PRD §10). Canonical strings: "Copied", "Unknown vendor", "Not a valid MAC address"; state labels "Found" / "Not found" / "Invalid".
- **Form-factor / surface:** Single surface — the Chrome desktop popup (MV3, ≤ 800×600, mock at 360 px wide). No other surfaces in v1.
- **Journeys:** UJ-1 (Jared pastes a MAC from a switch CLI → three formats + Vendor, one-click Cisco-dot copy, offline) and UJ-2 (Jared pastes junk → inline error, outputs cleared; valid-but-unmatched → "Unknown vendor" + prefix).
- **Concern scan:** dark mode (auto, live), keyboard access, color-not-alone, reduced motion, offline (no network), i18n (out of scope v1), multi-MAC paste (rejected → invalid).
